# FM-RB-EDIT — interactive rebase `edit` (mid-sequence stop)

## Current state (grounded)

`rebase_interactive(repo, onto, plan)` is an **in-memory one-shot executor**:
it cherry-picks each plan step onto an in-memory `tip` commit, building new
commits in the object DB, and only at the very end moves HEAD to the final tip
and checks out. The working tree and refs are untouched until completion.

Consequences:
- There is **no on-disk rebase state** during an interactive rebase.
- The conflict pause/resume (`git_rebase_open`, `rebase_in_progress`,
  `rebase_continue`) belongs to the **non-interactive** path (`git_rebase_*`)
  and is entirely separate — `edit` cannot reuse it.
- The executor already **aborts on a cherry-pick conflict** mid-replay
  ("interactive rebase conflict (aborted)") — a pre-existing limitation, not
  changed here.

## The gap + the hard part

`edit` means: stop *at* a marked commit with it checked out, let the user amend
it / make changes, then resume the **remaining** plan. Because the executor is
in-memory and one-shot, stopping mid-plan requires (a) materializing the partial
result on disk so the user can work, and (b) persisting the leftover plan so a
later `continue` can finish it. That persisted-plan-across-a-pause is the whole
slice.

## Design

- Add `edit` to `enum class rebase_action`; add `e` marking in the
  *git-rebase-todo* buffer.
- Refactor the executor loop into a helper `run_plan(repo, tip, steps, begin)`
  that applies steps from index `begin`. When it reaches an `edit` step:
  1. apply that commit onto `tip` (cherry-pick → new commit), as for `pick`;
  2. move HEAD to the new commit + checkout (materialize the partial result);
  3. write `<gitdir>/MG_REBASE_TODO`: line 1 = original HEAD oid (for abort),
     then one line per *remaining* step `"<char> <full-oid> <message>"`
     (char ∈ p/d/s/f/w/e; message only meaningful for reword/`w`);
  4. return `rebase_result::stopped`.
  Otherwise it finishes as today (move HEAD to final tip + checkout) → `done`.
- `rebase_interactive` returns `std::expected<rebase_result, error>` (was
  `void`); `done` / `conflicts` (existing in-memory abort case, surfaced not
  swallowed) / `stopped`.
- `rebase_continue`: if `MG_REBASE_TODO` exists, this is an interactive-edit
  pause — read the remaining plan, set `tip = HEAD` (the user's amended
  commit), `run_plan(...)` from there; on clean finish remove the file. Else
  fall through to the existing `git_rebase` continue.
- `rebase_abort`: if `MG_REBASE_TODO` exists, reset HEAD hard to the saved
  original oid + remove the file. Else `git_rebase_abort`.
- `rebase_in_progress`: true when a `git_rebase` is open **or**
  `MG_REBASE_TODO` exists.

## Bridge

- `mg_magit_rebase_interactive` returns the rebase code via `rebase_code`-style
  mapping: 1 done / 2 conflict / **3 stopped-for-edit** / 0 fail (extend the
  mapping with 3).
- `rebase_continue` / `rebase_abort` / `rebase_in_progress` already exist; their
  engine impls now also handle the MG_REBASE_TODO case — no signature change.

## UI

- *git-rebase-todo* (`magit_todomap`): add `e` to set a row's action to edit
  (renders `edit <oid> <summary>`); `struct magit_todo_entry.action` already has
  the int slot — add value 5 = edit, plumb into the `mg_magit_rebase_step`.
- After `C-c C-c` runs the plan: code 3 → ewprintf "Stopped for edit at <oid> --
  amend (c a), then r r to continue" and refresh; the **Rebasing** status
  section already keys off `rebase_in_progress`, which now covers the edit stop,
  so `r r` / `r a` work unchanged.

## TDD

1. Engine: a plan `[pick C2, edit C3, pick C4]` onto C1 → `rebase_interactive`
   returns `stopped`, HEAD is at the replayed C3, `MG_REBASE_TODO` exists,
   `rebase_in_progress` true. Amend HEAD (add a file), `rebase_continue` →
   `done`, C4 replayed on top, file gone, history linear.
2. Engine: after a `stopped`, `rebase_abort` restores the original branch tip
   and removes the file.
3. Bridge: `mg_magit_rebase_interactive` with an edit step returns 3; after a
   commit, `mg_magit_rebase_continue` returns 1.
4. tmux: `r i` → mark a commit `e` → `C-c C-c` → Rebasing section → amend →
   `r r` → complete.

## Out of scope (unchanged limitations)

- A cherry-pick **conflict** during the in-memory replay still aborts (the
  executor has never handled it; making interactive replay conflict-resumable
  is a separate, larger slice — it would mean persisting state on every step,
  not just at `edit`).
